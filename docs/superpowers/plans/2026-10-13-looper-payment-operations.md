# Looper Payment Operations Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents are available) or superpowers:executing-plans. Track every step with the checkboxes below.

**Goal:** Preserve the hardened Looper payment lineage, prove one manual follow-up, then run an hourly observation-only shadow for seven validated days without allowing races, mutable status, clock rollback, or scheduler edits to weaken the audit trail.

**Architecture:** All durable trust state lives under an absolute operator-selected state directory outside Git. Every mutation mode uses one OS flock lock from full ledger validation and archived-baseline revalidation through its terminal ledger append; immutable, closed-schema files and a hash-chained ledger are authoritative, while status and bounded logs are disposable projections. A safe launcher records lock contention even when it cannot enter the critical section, and both the shadow launcher and cron installer verify the successful manual proof from immutable ledger/report/artifact bytes.

**Tech Stack:** Node.js 24 CommonJS, node:test, existing canonical/domain-hash and payment-observer modules, /usr/bin/flock, crontab, canonical JSON, SHA-256, mode 0600 files/0700 directories, checked writes plus file and directory fsync.

Bootstrap accepts exactly these regular, non-symlink source files and no substitutes:

- $BASELINE/roster-proof-v1.json -> $STATE/baseline/roster-proof-v1.json
- $BASELINE/checkpoint-v1.json -> $STATE/baseline/checkpoint-v1.json
- $BASELINE/artifact-v2-a.json -> $STATE/baseline/artifact-v2-a.json

There are two deliberately different byte contracts. `canonicalFileBytes(value)` is exactly UTF-8 `canonicalStringify(value) + "\n"` (one LF, no BOM or CRLF), and whole-file SHA-256 is computed only over those bytes. `canonicalSemanticBytes(material)` is exactly UTF-8 `canonicalStringify(material)` with **no** trailing LF. Every domain commitment is `sha256(domain || canonicalSemanticBytes(schemaSpecificMaterial))`; its schema-specific material excludes only the commitment/ID field being computed, while preserving referenced lineage hashes and other semantic hash fields. Never compute a semantic commitment from serialized file bytes, and never compute a file hash from semantic material. For the baseline and every derived checkpoint/artifact, do not invent replacement projections: call the current `buildRosterHash` projection/algorithm from `normalize.js`, `buildRosterProofCommitment` (whose `proofMaterial` excludes `rosterProofCommitment`) from `roster-proof.js`, `buildCheckpointHash` from `checkpoint.js`, and the current `buildObservationArtifact`/`validateCompleteArtifact` algorithm from `artifact.js` (the `LOOPER-PAYMENT-ARTIFACT-v2\0` domain over the normalized artifact base with `artifactHash` excluded). Operations-schema IDs and domain hashes follow the same no-LF, self-field-excluded rule using their exact material builders.

Bootstrap validates all three source values and canonical file bytes, recomputes semantic commitments with those current builders, requires all three fixed file SHA-256 literals and semantic pins above, publishes them exclusively, and records all three destination paths, fixed file SHA-256 values, semantic domain hashes, and the roster proof commitment in genesis. Before **every** manual, scheduled, recovery, validation, gate, review, or retention continuation, while holding the mutation lock when mutation is possible and before RPC/build work, resolve and revalidate the required bytes against genesis plus the fixed pins. Any unresolved or changed byte fails closed.

Empty-ledger bootstrap is restartable: inspect the three final archive paths before writing; reuse each existing regular, non-symlink file only when its bytes, file SHA-256, domain hash, and semantic validation match the corresponding pin; publish each missing file; then reread all three and append genesis. A mismatching existing final file, unexpected final path, or changed partial archive fails closed without overwrite, deletion, or genesis. Thus a crash after any subset of archive links but before genesis is recovered by publishing only the missing matching files.

### Closed schemas and global bounds

Implement one exact-key validator per schema. Reject unknown/missing keys, accessors, non-plain objects, duplicate JSON keys, noncanonical JSON/timestamps/decimals, symlinks, traversal, and invalid UTF-8. JSON integers are safe integers. u64 is a canonical decimal string ^(0|[1-9][0-9]{0,19})$ whose value is at most 18446744073709551615; block/count values use u64. hash is ^sha256:[0-9a-f]{64}$; block hash is ^0x[0-9a-f]{64}$; address is lower-case ^0x[0-9a-f]{40}$; time is UTC millisecond YYYY-MM-DDTHH:mm:ss.sssZ; runId is ^run-[0-9a-f]{64}$; attemptId is ^run-[0-9a-f]{64}-a(000[1-9]|00[1-9][0-9]|0[1-9][0-9]{2}|[1-9][0-9]{3})$. Paths stored in JSON are state-relative POSIX paths, 1..240 ASCII chars, with no empty, dot, or dot-dot segment. General labels are 1..128 chars; bounded messages are 1..1024 chars; error detail is 0..4096 chars and never contains secrets or stacks.

Hard limits per file: ledger entry and run descriptor 256 KiB; report 1 MiB; status 256 KiB; alert/contention/batch/recovery/review-decision/retention-receipt 64 KiB each; roster/checkpoint/anchor/collection/artifact 64 MiB each. Behavioral limits: at most 5 attempts/run, 3 catch-up runs/invocation, 10,000 blocks/run, 1,000,000 transfers or receipts/report, 16 evidence hashes/alert, 100 contention records/batch, and 1,000 alerts/status projection. Check size before allocation and again on the opened file; reject growth during read.

Before every immutable publication, compute the projected count and bytes for its complete append-only class and for their global sum, using no-follow enumeration under the mutation lock. The ceilings are: ledger 10,000 files/64 MiB; runs recursively 250,000 files/64 GiB; alerts 10,000 files/640 MiB; contention as an aggregate 200,000 files/2 GiB; scheduler backups 10,000 files/10 GiB; review decisions 100 files/8 MiB; retention receipts 1,000 files/64 MiB; quarantine recursively 10,000 files/4 GiB; global 491,100 files/81 GiB. The contention aggregate permanently reserves 3,072 regular-file entries and 128 MiB for the spool (per slot: one claim plus, during no-replace publication, both hard-linked temp and ready names for one at-most-64-KiB payload inode), so records+batches may consume at most 196,928 files and 1,920 MiB; global append-only admission likewise treats the full 3,072-entry/128-MiB spool reservation as consumed regardless of current occupancy. The 1,024 precreated slot directories are fixed bootstrap structure and can never grow. Baseline is fixed at three files, status is one replaceable file, and logs have the separate 25 MiB cap. Exceeding either class or global count/bytes fails before temp creation with STORAGE_LIMIT; reserve the final 100 alert slots and 1 MiB of the alert class for storage-limit alerts only, and fail silently closed if even that reserve is exhausted.

### Archive-aware evidence resolution and one eligibility predicate

Every read of a ledger-linked path uses one `resolveEvidence(path, expectedFileHash, expectedDomain)` implementation in ledger validation, manual-proof validation, observation-gate derivation, recovery, review, archive planning, archive re-entry, and deletion. It first performs a no-follow bounded local read. If the local file is absent (not malformed), it scans retained local receipts by canonical path order and requires exactly one validated receipt whose validated manifest contains that exact path. Resolution is strictly receipt -> manifestLocator -> canonical manifest bytes -> manifest entry -> archived canonical file bytes: validate the local receipt file/domain hash; read the file-only locator without following links or escaping its archive root; validate canonical manifest file bytes, manifest file/domain hashes, archiveId, totals, and decision binding; then read the archived relative path no-follow and revalidate size, whole-file SHA-256, canonical JSON bytes, schema, and the schema-specific no-LF semantic domain commitment against both the manifest and ledger expectation. Missing, ambiguous, duplicated, network, changed-during-read, noncanonical, hash-mismatched, domain-mismatched, or symlinked evidence fails closed. A local and archived copy may coexist only when their canonical bytes are identical; disagreement fails closed. Baseline and ledger are always local and never use archive fallback.

Define `sourceTimestamp(path, validatedLedger)` and `isArchiveEligible(path, decision, trustedNow)` once and call them unchanged from validation, archive enumeration, manifest construction, crash re-entry, and source deletion. Eligibility requires an approve-archive decision, `trustedNow >= retainUntil`, source timestamp <= `reviewedThrough`, a closed/terminal owner where required, and the exact class rule below; no caller may approximate eligibility from mtime, ctime, directory name, current wall-clock age, or manifest membership alone.

| Exact class/path | Immutable source timestamp | Archive/delete eligibility |
|---|---|---|
| `baseline/*.json` | genesis `recordedAt` | Never; retained locally indefinitely. |
| `ledger/*.json` | entry `recordedAt` | Never; retained locally indefinitely. |
| `runs/<runId>/run.json`, `checkpoint.json`, `continuity-anchor.json` | `recordedAt` of the terminal ledger event that closes that run | Eligible only after that terminal event; open/pending/abandoned-with-unresolved-attempt runs are ineligible. |
| `runs/<runId>/attempts/<attemptId>/collection.json`, `artifact-a.json`, `artifact-b.json`, `report.json` | `recordedAt` of the terminal ledger event that closes that attempt | Eligible only after that exact terminal event; dangling attempts and unreferenced files are ineligible. |
| `runs/<runId>/recoveries/<recoveryId>.json` | matching `recovery-recorded.recordedAt` | Eligible only when file/domain hashes are bound by that event. |
| `contention/records/<contentionId>.json` | record `observedAt` | Eligible only if referenced by a validated batch that is referenced by a valid alert. Spool slots are never manifest entries. |
| `contention/batches/<batchId>.json` | batch `createdAt` | Eligible only if referenced by a valid alert. |
| `alerts/<alertId>.json` | alert `createdAt` | Eligible. |
| `scheduler/backups/<timestamp>-<sha256>.crontab` | canonical UTC-millisecond filename timestamp | Eligible only after its filename hash and bytes validate and no installed managed span references it. |
| `quarantine/pre-pin/<quarantineId>/**` | validated quarantine manifest `createdAt` | Eligible as one complete manifest-bound tree; opaque children use the manifest timestamp and may never satisfy ledger evidence. |

| `status/current.json`, `logs/**`, `contention/spool/**`, temp files, and unknown paths | none | Never included in a manifest; disposable projections follow only their own bounded replacement rules, while unknowns fail archive planning. |

For a run closed by abandon-run, only files bound by run-pinned or a closing attempt/recovery event are eligible; opaque/unbound attempt debris is not. The controlling decision and all receipts remain local so resolution never depends on an already archived trust root. Deletion accepts exactly the manifest entry set recomputed by this predicate at re-entry, and removes a source only after `resolveEvidence` proves the archived copy; manifest membership by itself is insufficient.

| attempt-started | recovery-recorded(mark-attempt-failed) | No valid report; closes the attempt without advancing and leaves the run retryable. |
| attempt-started | recovery-recorded(finalize-failed) | Valid failed report; closes without advancing and leaves the run retryable. |
| attempt-started | recovery-recorded(finalize-succeeded) | Valid successful report/artifacts; closes the run and advances exactly as attempt-succeeded. |
| run-pinned, attempt-failed, mark-attempt-failed, or finalize-failed | attempt-started | Same immutable run/anchor/range, next attempt, at most five. |
| Any open run with no active attempt | recovery-recorded(abandon-run) | Closes run without advancing predecessor; required after retry limit/operator abandonment. |
| Closed success/no-work/abandon | run-pinned | Next run derives only from the validated continuity head. |

All other transitions fail validation. Every invocation gets a new attempt ID; retries never overwrite files or change the run. A failed attempt may retry only the identical descriptor/checkpoint/anchor bytes and all run-pinned file/domain hashes.
